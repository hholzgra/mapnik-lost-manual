.TextSymbolizer face name
[#example-textsymbolizer-face-name]
====
`face-name` takes the full name of a font face, family name and style, like `Noto Sans Bold`; the family name alone is not enough. Mapnik checks the name when loading the style, an unknown face name is an error in strict mode. `mapnik.FontEngine.face_names()` in Python lists the available face names.

Unlike most other text attributes `face-name` and `fontset-name` do not accept expressions, so the font can't be taken from a data column. To use different fonts for different features, use a separate rule with a filter for each font.

.TextSymbolizer lang
[#example-textsymbolizer-lang]
====
Chinese, Japanese and Korean share many Unicode characters whose written forms differ between these languages. Fonts covering all of them, like the Noto Sans CJK fonts used here, contain the different glyph variants, and the text language decides which one is used. Without `lang` Mapnik guesses the language from the script of the text, which for Han characters is always simplified Chinese.

To a lesser extent Serbian and Macedonian Cyrillic differ from Russian Cyrillic for certain characters, too, and there are some other minor cases, too.

Fonts without language specific variants are not affected by `lang` at all.

.TextSymbolizer font feature settings
[#example-textsymbolizer-font-feature-settings]
====
`font-feature-settings` turns optional OpenType font features on or off, like `smcp` for small capitals, `c2sc` for turning capitals into small capitals, too, `onum` for old style numerals or `frac` for fractions. Each comma separated entry is a feature tag, optionally followed by a value, so `smcp`, `smcp 1` and `smcp=1` all enable small caps, while `-liga` or `liga 0` disable a feature.

Features only have an effect if the font provides them; unsupported ones are silently ignored. The example uses Noto Serif, which supports small caps. Tools like `otfinfo -f` list the features a font file supports.

The attribute can also be set on `<Format>` to apply features to a part of the text only.

.TextSymbolizer placement
[#example-textsymbolizer-placement]
====
`placement` Controls where the text is actually placed:

`point`:: Places the text just once at the center of the geometry. In case of a polygon that may actually be outside of the polygon surface, depending on its shape

`interior`:: Similar to `point`, but makes sure that the text is placed inside a polygon even if its center point is actually on its outside

`line`:: When `spacing` is larger than zero the text is repeatedly printed along a line or a polygons outline with `spacing` pixels between texts

`vertex`:: Tries to place the text on each vertex point of a line or a polygons outline

`grid`:: When `grid-cell-width` and `grid-cell-height` are greater than zero the text is repeatedly printed into a polygons surface, using grid cells of the given width and height. Note that the text is not clipped at the border of the polygon, so some text may be printed slightly outside of the polygon surface.

`alternating-grid`:: Similar to `grid`, but each second row is horizontally displaced by half of `grid-cell-width`

.TextSymbolizer horizontal alignment
[#example-textsymbolizer-horizontal-alignment]
====
The red dots mark the label positions. `horizontal-alignment` decides on which side of its position a label is placed. The default `auto` uses `right` if `dx` is positive, `left` if it is negative, and `middle` otherwise, so that a displaced label extends away from its point.

With `placement="line"` the additional value `adjust` stretches a label over the full length of its line by spreading its characters evenly. As the label then takes up the whole line, `spacing` is ignored and only one label is placed per line.

.TextSymbolizer orientation and rotate-displacement
[#example-textsymbolizer-orientation]
====
`orientation` rotates a label counterclockwise around its position. The `dx`/`dy` displacement is not rotated along with it by default, so in the top row the labels stay to the right of their points. With `rotate-displacement="true"`, in the bottom row, the displacement is rotated, too, and a label rotated by 90° ends up above its point, one rotated by 180° to the left of it.

.TextSymbolizer largest bbox only
[#example-textsymbolizer-largest-bbox-only]

With `largest-bbox-only` enabled, the default, only the part with the largest bounding box gets a label; with it disabled, each part is labeled separately. .TextSymbolizer upright
[#example-textsymbolizer-upright]
====
Each row uses one `upright` value on two horizontal lines, the left one drawn from left to right, the right one from right to left, as the arrow heads show. `right` always runs the text in the direction the line was drawn, `left` against it, even if this turns the text upside down. `auto`, the default, picks whichever of the two directions keeps the text readable, `auto-down` picks the other one; on horizontal lines this always gives upside down text, so `auto-down` is mostly useful on near-vertical lines, see the <<example-textsymbolizer-upright-steep,next example>>. `left-only` and `right-only` never flip the text: they place it like `left` and `right`, but drop the label instead if more than half of its characters would end up upside down.

.TextSymbolizer upright on steep lines
[#example-textsymbolizer-upright-steep]
====
`auto` and `auto-down` only look at the angle of the line on the map, not at the direction it was drawn in: `auto` runs the text towards the right, `auto-down` towards the left. On near-vertical lines this decides whether text reads from bottom to top or from top to bottom. With `auto`, lines leaning to the right, like `/`, get text reading bottom to top, and lines leaning to the left, like `\`, get text reading top to bottom; `auto-down` does the opposite. Either way the reading direction flips when a line crosses the vertical, so labels on almost vertical lines that wobble slightly may change direction from one line to the next.
