# Mapnik - The Missing Manual

AsciiDoc book documenting Mapnik's XML style format, published at
http://get-map.org/mapnik-lost-manual/. `book.adoc` is the master
file, chapters live in `chapters/`, example styles in `examples/`.

## Scope

- The book documents Mapnik 4.x only. Don't add notes about legacy
  2.x/3.x behaviour; document 4.x behaviour and defaults.
- Attributes, values and behaviour are verified against the Mapnik
  source and the installed build, not taken from the Mapnik wiki or
  mapnik.org docs, which are incomplete and partly outdated.

## Environment

- Mapnik source: `~/for-git-pull/mapnik` (not `~/mapnik`), a git
  checkout of current master including the ArcSymbolizer.
- Python bindings: `~/for-git-pull/python-mapnik`, installed into the
  venv `~/for-git-pull/pymapnik-venv`. Always
  `source ~/for-git-pull/pymapnik-venv/bin/activate` before rendering
  examples or running the tools.
- Rebuilding Mapnik: build the .deb from the source tree and install it
  with `sudo apt install --reinstall ./mapnik-*.deb` (same version
  string, so a plain install is skipped). Rebuild the bindings against
  it with `SYSTEM_MAPNIK=1 python -m build --wheel --no-isolation`, then
  `pip install --force-reinstall --no-deps dist/*.whl`.

## Building and checking

- `make` builds all formats into `build/`; `make html|pdf|epub|multipage`
  for single ones.
- `make check` renders all examples (`tools/check-examples.sh`, `-f` to
  force) and builds the epub with `--failure-level=WARN`. Quick book
  check: `asciidoctor-epub3 --failure-level=WARN -a mapnik-arc -o
  /dev/null book.adoc`.
- `make check-attributes MAPNIK_SRC=~/for-git-pull/mapnik` (or
  `tools/check-attributes.py --mapnik-src ...`) compares the attribute
  tables with what Mapnik accepts, finds undocumented attributes,
  differing defaults, and missing/wrong version markers (see below).
  False alarms go into `tools/attributes-ignore.txt`.
- Pre-commit hooks (`.pre-commit-config.yaml`): make check, codespell,
  asciidoc-linter, flake8. The linter binary can be run directly from
  the pre-commit cache; it wrongly reports book.adoc's header
  (docToolchain/asciidoc-linter#55).
- The ArcSymbolizer chapter and examples are only included when the
  installed Mapnik has it (`ARC_SUPPORT`, AsciiDoc attribute
  `mapnik-arc`).
- The Makefile is non-recursive: `examples/Makefile` and
  `examples/data/Makefile` are fragments of the top level one and only
  delegate to it when make is run inside those directories.
- Dependencies in `.deps/` are generated by `tools/adoc-deps.py` and
  `tools/mapnik-deps.py`.

## Writing conventions

- `book.adoc`'s header must not contain empty lines: the header ends at
  the first one, and header-only attributes like `:source-highlighter:`
  after it are silently ignored.
- Chapter files that include examples set `:sourcedir:` themselves
  (e.g. `:sourcedir: ../..`) and use
  `include::{sourcedir}/examples/...xml[]` plus
  `image::examples/...svg[align="center"]`.
- Attribute tables: one row per attribute (name, type, default,
  description). Link the name to its section or example with
  `<<id,name>>`; sections use ids like `[#layer-sort-by]`, examples
  `[#example-layer-sort-by]`.
- Version markers: attributes added after Mapnik 4.0.0 get a
  `{since-X-Y-Z}` reference at the end of their description,
  unreleased ones `{since-next}`. The attributes are defined in the
  `book.adoc` header; add a new one there for each new version. A
  whole new element gets one marker in its chapter text instead of
  one per row. `check-attributes` verifies the markers against the
  Mapnik release tags.
- Examples using such attributes set `minimum-version` on `<Map>`.

## Examples

- One style per example under `examples/` (`Symbolizer/<Type>/`,
  `layer/`, `map/`, ...), rendered by `examples/render.sh` to `.svg`
  and `.png` next to the `.xml` (600x300, zoomed to the data plus a
  margin). Rendered images are not committed.
- Use inline CSV datasources where possible. The CSV plugin types
  `true`/`false` as booleans, so filters need `[col] = true`, not
  `'true'`.
- Shared symbols are in `examples/symbols` (`<FileSource
  name="symbols">./symbols</FileSource>`); Natural Earth shapefiles are
  downloaded into `examples/data` by make.
- Check renders visually (look at the PNG) before referencing them;
  labels that silently fail to place are a common pitfall.

## Repository layout

- `notes/`: research and plans (e.g. findings on undocumented
  attributes), not part of the book.
- `tools/`: Python scripts, keep lines at most 75 characters.
- `TODO`: the author's open items and questions.

## Git

- Commit only when asked; the author usually commits themselves.
- Leave unrelated uncommitted changes in the working tree alone.
